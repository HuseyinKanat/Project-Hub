# Frontend

> React 18 + Vite + Tailwind + shadcn/ui-style component layer that consumes the [[components/backend]] REST API plus an MCP-over-HTTP control surface and renders the live ProjectHub kanban + ticket workspace, with real-time updates via a self-managed WebSocket hook.

## Current behavior

The frontend is a single-page React 18 app bundled with Vite 5 (`vite.config.ts`), strict TypeScript (`tsconfig.json`, `noUncheckedIndexedAccess`, `strict: true`), and Tailwind 3 (`tailwind.config.js`) for styling. It boots from `src/main.tsx`, which mounts `<App />` inside a top-level `QueryClientProvider` (TanStack Query 5, `retry: 1`, `refetchOnWindowFocus: false`). `src/App.tsx` wraps everything in `ThemeProvider` and `BrowserRouter` and declares the route table: a public `/login` and an `Outlet`-style protected shell (`RequireAuth → Layout`) that hosts `/` (Boards index), `/boards/:boardKey` (BoardDetail kanban), `/boards/:boardKey/settings` (BoardSettings + WorkflowEditor + MembersTab + PermissionMatrix), and `/boards/:boardKey/tickets/:ticketKey` (TicketDetail). The `Layout` shell (`src/components/Layout.tsx`) renders the persistent header (logo, Boards nav, `NotificationBell`, `ThemeToggle`, logout button) plus the `Outlet` for nested routes.

Backend communication is centralized in `src/api/client.ts`, which exposes a flat `api` object (a hand-rolled `request<T>` helper plus typed methods for boards, tickets, transitions, claims, comments, history, notifications, board membership, and actor listing). Two transports are used in parallel against the same backend: REST under `/api/*` for everything user-facing (boards, tickets, comments, notifications, auth/me, membership) and an MCP-over-HTTP envelope (`mcpCall<T>` → `POST /mcp/call/{tool}`, unwraps the `{ tool, result }` envelope) for workflow operations (`list_workflows`, `create_workflow`, `update_workflow`, `add_transition`, `set_field_gates`, `activate_workflow`, `ensure_board_workflow`, `delete_workflow`, `delete_state`). Both surfaces share auth via `getStoredToken()` from the Zustand auth store (`src/stores/auth.ts`); a bearer token is read from `localStorage["projecthub.token"]` and attached to every request. On `401` both helpers call `useAuth.getState().logout()`, clearing the token and triggering `RequireAuth` to redirect to `/login`. Errors are normalized into an `ApiRequestError` class carrying the HTTP status plus the parsed `{ error, message, detail }` body so call sites can surface backend domain errors (`invalid_transition`, `field_gate_not_met`, `permission_denied`) verbatim. Vite proxies `/api` and `/mcp` to `http://backend:8000` in dev (`vite.config.ts`), and the `@/*` import alias maps to `src/*`.

State management is intentionally lean. TanStack Query owns server cache; mutations invalidate keyed queries to refetch board/ticket state after writes. Zustand only holds the auth token (`useAuth`) — there is no global UI store. Real-time updates flow through `src/hooks/useWebSocket.ts`, a 400-line custom hook that opens `ws(s)://<host>/ws/boards/:boardId?token=<bearer>` and pumps `EventEnvelope` messages from the backend Redis bus into React state. It implements: ping-pong heartbeat (default 30 s) with latency-derived `ConnectionQuality` (`excellent | good | poor | disconnected`), exponential-backoff reconnect with jitter (base 2 s, ×1.5, cap 30 s, max 10 attempts), structured `error` / `system_degradation` message routing, a connection-timeout watchdog (default 15 s), and stable callback refs so consumers can hot-swap `onMessage` without forcing reconnects. Pages call `useWebSocket({ boardId, token, onMessage })` and `queryClient.invalidateQueries(...)` inside their `onMessage` handler to keep the kanban + ticket views live. Theming (since F1/PH-170) is a **CSS-variable token layer** ("Cyan on Black" design system): `src/index.css` carries a dark `:root` (default) + `html.light` override copied verbatim from `.claude/skills/ProjectHub Design System/colors_and_type.css`, and `tailwind.config.js theme.extend` maps every semantic utility to `var(--token)` (e.g. `surface: "var(--bg-surface)"`) rather than baked hexes. `darkMode` is `["selector", "html:not(.light)"]` — **dark is the default**, `ThemeProvider` toggles a `.light` class (NOT `.dark`), with localStorage persistence + `prefers-color-scheme: light` seeding. Surfaces consume token utilities (`bg-surface`, `text-text-primary`, `border-hairline`, `text-accent`, `font-mono`); the `html.light` override repaints the same utility so the ~735 historical `dark:` variants get dropped (not rewritten) as F2–F8 migrate. Inter is self-hosted under `frontend/public/fonts/` (12 weights+italics via `@font-face`); JetBrains Mono via Google Fonts `@import` is semantic (SHAs, ticket keys, branches). State-color resolution lives in `src/lib/stateColor.ts`, which prefers a per-workflow-state `color` hex (rendered at 10 %/30 % alpha for background/border — theme-agnostic, unchanged) and falls back to a `STATE_CATEGORIES`-keyed token-utility class. Ticket markdown rendering uses `react-markdown` + `remark-gfm` (`MarkdownRenderer.tsx`) with `MermaidBlock.tsx` upgrading fenced ```mermaid blocks into diagrams via the `mermaid` lib. The workflow editor (`components/WorkflowEditor.tsx`, ≈ 27 KB) is built on `@xyflow/react` (formerly React Flow) for visual state/transition editing, with sortable dnd via `@dnd-kit/core` + `@dnd-kit/sortable`. TypeScript domain types live in `src/types/api.ts` (`Priority`, `TicketType`, `AgentPhase`, `ActorSummary`, `WorkflowState`, `FieldGates`, etc.) and are kept in lockstep with the backend via `npm run generate:types` (openapi-typescript script, per `frontend/README.md`). All dev/build/test commands run inside the `frontend` Docker container per the project's container-only rule (`rules.md` §1): `docker compose exec frontend npm run typecheck | lint | dev | build`.

## Design decisions (recent)

- F6 lane colors are CSS-var reference strings, not hex or a JS theme branch [PH-175] — `branchGraphLayout.ts LANE_COLORS` holds `"var(--lane-cyan)"…` strings; `laneColor(lane)` returns them verbatim and every call site feeds them straight into SVG `stroke`/`fill` or inline `style`. SVG and inline styles resolve CSS custom properties at paint, so a single string repaints under `html.light` (which redefines `--lane-*`) — theme-aware lanes for free, zero JS theme logic, `laneColor` signature frozen. Order is kit-aligned (cyan=lane 0=accent=default branch). The two-pass `assignLanes` algorithm + `LANE_W`/`ROW_H` are byte-identical (visual-only ticket).
- F6 selection vs new-commit are distinct, motion-safe treatments [PH-175] — selected commit row = static `bg-accent-soft` + left cyan hairline (`border-l-2 border-hairline-cyan`) and a hollow dot (`fill="var(--bg-base)"` + lane-colored ring); new-commit row (in `highlightedShas`) = one-shot `.animate-glowin` (`@keyframes ph-glowin` accent-soft→transparent, added to `index.css @layer utilities`) + dot `drop-shadow(var(--accent))`. The two never visually collide (static tint+hairline vs transient fade). The global `prefers-reduced-motion` block in `index.css` caps the animation duration for free — no per-component media query — and the static selection stays visible regardless of motion pref. Adding one keyframe utility to `index.css` is the only non-component edit and is purely additive (no token block touched).

- NEVER string-concat a hex alpha suffix onto a `var()` color [PH-175] — once `LANE_COLORS` became `var(--lane-*)` strings (F6), the old CommitRow ref-chip `backgroundColor: color + "22"` (lane hex + alpha) silently produces the invalid CSS value `"var(--lane-cyan)22"` → the chip background fails to paint (chip looks empty). **tsc does NOT catch it** (still a `string`); build stays green; only an eyeball/inspect reveals the missing tint. Fix used: `backgroundColor: color-mix(in srgb, ${color} 14%, transparent)` (the F1-sanctioned one-off alpha path, same as PH-170/PH-172). Any future per-lane tint (dots, chips, soft fills driven by `laneColor()`) MUST use `color-mix`, never `+ "NN"`. Grep touched files for `+ "` / template hex-alpha before committing a lane-color change.
- `@apply` of var-backed token utilities fails under Vite's PostCSS pass [PH-170] — `@apply bg-accent-strong` / `text-text-on-accent` / `bg-accent-soft` AND custom-radius `@apply rounded-pill` / `rounded-md` throw `The <class> class does not exist` in the DEV server (the standalone `npx tailwindcss` CLI and `npm run build` tolerate them, so build-green is NOT sufficient — the dev server 500s the CSS module and the app renders unstyled).
